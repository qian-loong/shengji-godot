# C6 升级结算

> **Status**: Designed
> **Author**: user + game-designer
> **Last Updated**: 2026-07-27
> **Implements Pillar**: 支柱 2（规则即策略）

## Overview

**升级结算系统**负责对局结束时的最终计算：合并出牌阶段得分与抠底分值，判定攻守双方的升级结果，处理不可跳过级的约束，并更新 current_rank。本系统是一局与下一局之间的桥梁——它的输出直接决定下一局的级牌和庄家归属。

## Player Fantasy

结算是整局博弈的最终揭晓——"我们赢了多少分？升几级？有没有被抠底翻盘？"抠底倍数的存在让最后一墩充满悬念。本系统服务的情感是**结果张力**——分数揭晓时的紧张与满足。

## Detailed Design

### Core Rules

#### 1. 最终得分计算

```
calculate_final_score(attack_score: int, bottom: Card[], last_trick_winner: TeamSide, last_trick_type: CardType, last_trick_pair_count: int) → int
```

流程：
1. 基础分 = C5 提供的 `attack_score`（出牌阶段攻方累计得分）
2. 如果攻方赢得最后一墩：
   - 计算底牌分值：`bottom_score = sum(card_score(c) for c in bottom)`
   - 计算抠底倍数：`multiplier = get_bottom_multiplier(last_trick_type, last_trick_pair_count)`（F3 已定义公式）
   - 最终得分 = `attack_score + bottom_score × multiplier`
3. 如果庄家方赢得最后一墩：
   - 最终得分 = `attack_score`（底牌分值不计入）

#### 2. 升级阶梯

**经典模式 (Classic)** 和 **快速模式 (Quick)** 升级表：

| 攻方最终得分 | 结果 | 谁升级 | 升几级 |
|-------------|------|--------|--------|
| = 0 | 庄家大胜 | 庄家方 | 3 级 |
| 1–39 | 庄家小胜 | 庄家方 | 2 级 |
| 40–79 | 庄家守庄 | 庄家方 | 1 级 |
| 80–119 | 庄家下庄 | 无（仅换庄） | 不升 |
| 120–159 | 庄家下庄·攻方小胜 | 攻方 | 1 级 |
| 160–199 | 庄家下庄·攻方大胜 | 攻方 | 2 级 |
| ≥ 200 | 庄家下庄·攻方全收 | 攻方 | 3 级 |

> **术语**：下庄的主语是**当前庄家**（失去庄权）。攻方达到门槛导致庄家下庄；攻方本身不是庄，不说「攻方下庄」。

**竞技模式 (Competitive)** 升级表（高门槛，渐进升级）：

| 攻方最终得分 | 结果 | 谁升级 | 升几级 |
|-------------|------|--------|--------|
| = 0 | 庄家大胜 | 庄家方 | 3 级 |
| 1–39 | 庄家小胜 | 庄家方 | 2 级 |
| 40–79 | 庄家守庄 | 庄家方 | 1 级 |
| 80–99 | 攻方分数不足 | 无 | 不换庄，不升级 |
| 100–149 | 庄家下庄 | 无（仅换庄） | 不升 |
| 150–199 | 庄家下庄·攻方小胜 | 攻方 | 1 级 |
| 200–249 | 庄家下庄·攻方大胜 | 攻方 | 2 级 |
| ≥ 250 | 庄家下庄·攻方全收 | 攻方 | 3 级 |

**快速模式 (Quick)** 升级表（低门槛，快速推进；与代码 `PRESET_QUICK` 一致）：

| 攻方最终得分 | 结果 | 谁升级 | 升几级（表×step2） |
|-------------|------|--------|-------------------|
| = 0 | 庄家大胜 | 庄家方 | 3×2 = 6 级 |
| 1–29 | 庄家小胜 | 庄家方 | 2×2 = 4 级 |
| 30–59 | 庄家守庄 | 庄家方 | 1×2 = 2 级 |
| 60–89 | 庄家下庄·攻方小胜 | 攻方 | 1×2 = 2 级 |
| 90–119 | 庄家下庄·攻方大胜 | 攻方 | 2×2 = 4 级 |
| ≥ 120 | 庄家下庄·攻方全收 | 攻方 | 3×2 = 6 级 |

以上阈值均可通过 F3 `upgrade_table` 配置。快速模式的实际升级数 = 表中级数 × `upgrade_step`(2)。

#### 3. 不可跳过级

某些级在升级时不可跳过（可配置，默认 5、10、K）：

```
apply_upgrade(current_rank: Rank, levels: int, no_skip_ranks: Rank[]) → Rank
```

算法：
```
rank = current_rank
for i in 1..levels:
    rank = next_rank(rank)  // 按 2,3,4,...,K,A 顺序
    if rank in no_skip_ranks and i < levels:
        return rank  // 遇到不可跳过级，停在此处
return rank
```

示例（no_skip = [5, 10, K]）：

| 当前级 | 升级数 | 目标 | 实际结果 | 原因 |
|--------|--------|------|---------|------|
| 4 | 2 | 6 | 5 | 5 不可跳过 |
| 4 | 1 | 5 | 5 | 正好到 5，无跳过 |
| 5 | 2 | 7 | 7 | 从 5 出发，6→7 无阻挡 |
| 9 | 2 | J | 10 | 10 不可跳过 |
| Q | 2 | A | K | K 不可跳过 |
| K | 1 | A | A | 正好到 A |

#### 4. 下庄判定

- **条件**：攻方最终得分 ≥ `upgrade_threshold`（经典 80 / 竞技 100 / 快速 60）→ **庄家下庄**
- **语义**：失去庄权的是**当前庄家**，不是攻方。「下庄」主语始终是庄家；攻方是触发方
- **换庄**：下一局庄家 = 当前庄家逆时针下家 `(dealer_seat + 1) % 4`，该座位属于原攻方阵营
- **UI 文案**（与实现一致）：
  - 仅换庄、不升级 → `庄家下庄（不升级）`
  - 换庄且攻方升级 → `庄家下庄，{队名} 升 n 级`
  - 庄家方升级 → `庄家守庄，{队名} 升 n 级`

#### 5. 两队独立级

两支队伍各自维护独立的级（rank）：

```
team_ranks[0] = 队伍 [0,2]（南+北）的当前级
team_ranks[1] = 队伍 [1,3]（东+西）的当前级
team_index = seat % 2
```

- 每局打的级 = 庄家方的级（`team_ranks[current_dealer % 2]`）
- 结算后只更新**升级方**的级：`team_ranks[upgrading_team] = new_rank`
- **庄家下庄**但攻方不升级时（经典 80–119 / 竞技 100–149），两队级都不变

#### 6. 游戏结束条件

当一方需要打 A 级时（该队 rank = A），该局为"打 A"局。打完 A 级后（即该方在 A 级胜出并需要继续升级时），该方获胜，游戏结束。

### States and Transitions

C6 无持续状态。对局结束时执行一次计算，输出升级结果。

### Interactions with Other Systems

| 方向 | 系统 | 接口 |
|------|------|------|
| ← C5 分值追踪 | attack_score（出牌阶段攻方得分） |
| ← C4 抠底/配底 | 底牌 Card[]（用于计算底牌分值） |
| ← C7 对局状态机 | 最后一墩的赢家、牌型信息 |

## Formulas

### 抠底倍数（来自 F3）

| 最后一手牌型 | 倍数 |
|-------------|------|
| Single | 1 |
| Pair | 2 |
| Tractor(N对) | N × 2 |
| Dump | 取最大成分倍数 |

### 升级阈值表（可配置）

**经典模式 (Classic) 升级表**：
```gdscript
[
  [0, 0, 3],    # 0分 → 庄家升3级
  [1, 0, 2],    # 1-39分 → 庄家升2级
  [40, 0, 1],   # 40-79分 → 庄家升1级
  [80, 1, 0],   # 80-119分 → 庄家下庄，不升级
  [120, 1, 1],  # 120-159分 → 庄家下庄·攻方升1级
  [160, 1, 2],  # 160-199分 → 庄家下庄·攻方升2级
  [200, 1, 3],  # 200+分 → 庄家下庄·攻方升3级
]
```

**竞技模式 (Competitive) 升级表**（100分换庄，150分开始升级）：
```gdscript
[
  [0, 0, 3],     # 0分 → 庄家升3级
  [1, 0, 2],     # 1-49分 → 庄家升2级
  [50, 0, 1],    # 50-99分 → 庄家升1级
  [100, 1, 0],   # 100-149分 → 庄家下庄，不升级
  [150, 1, 1],   # 150-199分 → 庄家下庄·攻方升1级
  [200, 1, 2],   # 200-249分 → 庄家下庄·攻方升2级
  [250, 1, 3],   # 250+分 → 庄家下庄·攻方升3级
]
```

**快速模式 (Quick) 升级表**（与代码 `PRESET_QUICK` 一致；实际级数 = 表×`upgrade_step`）：
```gdscript
[
  [0, 0, 3],     # 0分 → 庄家升3（×step）
  [1, 0, 2],     # 1-29分 → 庄家升2（×step）
  [30, 0, 1],    # 30-59分 → 庄家升1（×step）
  [60, 1, 1],    # 60-89分 → 庄家下庄·攻方升1（×step）
  [90, 1, 2],    # 90-119分 → 庄家下庄·攻方升2（×step）
  [120, 1, 3],   # 120+分 → 庄家下庄·攻方升3（×step）
]
```

**表项格式**：`[min_score, upgrading_side, upgrade_levels]`
- `min_score`：触发该档的最低分数
- `upgrading_side`：0=庄家方，1=攻方（与代码 `upgrade_table` 一致；旧文档 1/2 编码已废弃）
- `upgrade_levels`：表内级数；实际升级数 = 级数 × `upgrade_step`（庄/闲同一乘数）

查表逻辑：找到 ≤ 最终得分的最大阈值，取对应结果；再乘 `upgrade_step`。

## Edge Cases

| # | 边界情况 | 处理方式 |
|---|---------|---------|
| E1 | **抠底翻盘**：出牌阶段攻方 70 分（未达下庄门槛），但赢最后一墩抠底后达 120 | 最终得分 = 120，**庄家下庄**且攻方升 1 级 |
| E2 | **底牌无分牌** | bottom_score = 0，倍数无意义，最终得分 = attack_score |
| E3 | **current_rank = A 且胜方需继续升级** | 游戏结束，该方获胜 |
| E4 | **current_rank = A 且庄家守庄（40–79 分）** | 不结束，庄家继续打 A |
| E5 | **升级跨越多个不可跳过级**：如当前 3 级升 3 级（3→6），但 5 不可跳过 | 停在 5 |
| E6 | **no_skip_ranks 为空** | 所有级均可跳过，正常升级 |
| E7 | **攻方得分恰好 = 阈值**（如 80、120） | 按该阈值处理（≥ threshold **庄家下庄**，≥ 120 攻方升 1） |

## Tuning Knobs

| 参数 | 类型 | 默认值 | 影响 |
|------|------|--------|------|
| `upgrade_table` | Array | [[0,0,3],[1,0,2],[40,0,1],[80,1,0],[120,1,1],[160,1,2],[200,1,3]] | 升级阶梯：`[最低分, 升级方(0庄/1攻), 升级级数]`，由 F3 承载 |
