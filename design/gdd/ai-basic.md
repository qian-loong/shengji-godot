# FT1 AI 基础决策

> **Status**: Designed
> **Author**: user + game-designer
> **Last Updated**: 2026-09-05
> **Implements Pillar**: 支柱 1（配合可感知）— MVP 阶段先保证规则正确，为后续配合意图打基础
> **S5-04 补章（2026-09-05）**: 新增 §4b「AI 自主决策（SMART 模式）」，关闭 Open Question Q2，`lead_strategy` 默认值改为 `SMART`。实现留 S5-05。

## Overview

**AI 基础决策系统**为 3 个 AI 玩家提供出牌决策能力。MVP 阶段的目标是"规则正确 + 基础合理"——AI 不会犯规，不会出明显愚蠢的牌，但不要求高水平博弈或搭档配合。本系统通过 C2 的 `get_legal_plays()` 获取合法出牌列表，然后用评分策略选择最优出牌。默认出牌模式 `SMART`（§4b）在"基础合理"范围内引入**攻守身份驱动**的自主决策——庄家方控场、攻方拿分——但不追求深度博弈，仍属"懂规则的对手"层次。

## Player Fantasy

AI 是玩家的对手和搭档。MVP 阶段玩家的期望底线是"AI 不犯规、不出太离谱的牌"。如果 AI 出了非法牌或明显的低级失误（如有主牌不出、明知必输还浪费大牌），玩家会立刻丧失游戏兴趣。本系统服务的情感是**合理感**——"AI 至少像个懂规则的人"。

## Detailed Design

### Core Rules

#### 1. AI 决策入口

```
ai_decide(seat_id: int, hand: Card[], game_state: GameState, rule_config: RuleConfig) → Card[]
```

AI 在以下时机被调用：
- **亮主阶段**：是否亮主、亮什么花色
- **配底阶段**（AI 为庄家时）：选哪些牌扣底
- **出牌阶段**：首出或跟牌选择

#### 2. 亮主决策

```
ai_bid_decision(hand: Card[], rule_config: RuleConfig) → BidDeclaration?
```

MVP 策略：
- 统计手中每个花色的级牌和王牌数量
- 如果有合法声明条件（满足 bid_requires_joker 等配置）：
  - 选择级牌/主牌最多的花色声明
  - 有 PairJoker 时优先声明公主
- 如果不满足声明条件 → 不声明（返回 null）

#### 3. 配底决策（AI 为庄家时）

```
ai_bury_decision(hand: Card[], bottom_size: int, trump_suit: Suit?, rule_config: RuleConfig) → Card[]
```

MVP 策略：
- 优先扣短门副牌（张数最少的副花色）
- 避免扣主牌（除非手牌主牌过多）
- 避免扣分牌（5/10/K），除非该副花色只有分牌无保护
- 目标：清掉 1-2 门副牌，增加主牌控制力

#### 4. 出牌决策

**首出决策**：

```
ai_lead_decision(hand: Card[], game_state: GameState, rule_config: RuleConfig) → Card[]
```

MVP 策略（按优先级）：
1. 如果主牌强势（主牌数量 > 平均值）→ 出主牌清主
2. 如果某副花色有绝对控制（最大牌）→ 出该花色拿分
3. 如果攻方（己方为攻方时）需要拿分 → 出含分牌的花色
4. 默认：出最短门副牌的小牌（减少被杀风险）

**首出策略开关（`AIPlayer.lead_strategy`）**

| 值 | 行为 | 用途 |
|----|------|------|
| `SMART` | 攻守身份驱动的自主决策（首出+跟牌，见 §4b） | **默认值**，玩家实际对局使用 |
| `SIMPLE` | 只首出单张 | 测试开关：批跑基线复现 |
| `MAX_STRUCTURE` | 优先首出最大结构：最长拖拉机 > 对子 > 单张 | 测试开关：激活对子/拖拉机规则路径 |
| `DUMP_HAPPY` | 在副牌域内尽量甩牌 | 测试开关：压测甩牌最大性校验 |

**默认值从 `SIMPLE` 切换为 `SMART`（S5-04 决策，2026-09-05）。** 历史上默认是
`SIMPLE`，实测 54387 墩首出 100% 是单张，导致 `allow_dump` /
`strict_follow_structure` / `tractor_allow_rank_card` / `four_same_is_tractor`
四个配置维度在随机批跑中完全不触发。曾考虑改默认为 `MAX_STRUCTURE` 以覆盖这些
路径，但它**不是经过设计的对局策略** —— 只会"能打最长拖拉机就打"，不区分攻守、
不留后手，实测把下庄率从 0.50 推到 0.75、对局墩数减少 29%。三个旧枚举因此
**降格为纯测试开关**，真实对局改由自主决策的 `SMART`（§4b）承担。

**批跑基线仍必须显式传 `--lead-strategy`。** SMART 含随机/局势依赖，不适合当
可复现基线；覆盖率补充跑与回归基线一律显式指定开关，与默认分开存放：

```bash
python tools/batch/run_batch.py <manifest> --lead-strategy simple --run-id baseline-xxx
python tools/batch/run_batch.py <manifest> --lead-strategy max_structure --run-id cov-xxx
```

构造牌局（`--scenario`）默认仍启用 `MAX_STRUCTURE`（压测用），可用 spec 的
`lead_strategy` 字段覆盖。

#### 4b. AI 自主决策（SMART 模式）

`SMART` 是玩家实际对局使用的**默认出牌模式**，接管**首出与跟牌全程**。
与 SIMPLE / MAX_STRUCTURE / DUMP_HAPPY 三个**固定行为的测试开关**不同，
SMART 让 AI 依据**攻守身份 + 记牌推断**自主判断每一手出什么。三个旧枚举
保留，仅供批跑与压测显式传参复现基线，不参与真实对局。

##### 决策主轴：攻守身份

一切 SMART 决策先按己方是庄家方还是攻方分流：

| 身份 | 出牌总倾向 | 战术目标 |
|------|-----------|---------|
| 庄家方（控场方） | 清主 / 抢控 / 主动甩铁最大结构 / 保结构 | 消耗对手保护、建立控制、守住庄 |
| 攻方 | 拿分 / 保守试探 / 拆结构保分 | 攒够升级门槛分，不轻易暴露大牌 |

##### 首出决策（SMART）

**庄家方首出：**
1. 若某结构（拖拉机 > 对子 > 单张）经记牌推断为该域**铁最大**
   → 首出该结构（含甩牌，见下）
2. 否则出小牌试探，保留大牌控场

**攻方首出：**
1. 若某副花色有**铁最大单张/结构**且该墩可能带分 → 出之拿分
2. 否则出最短门小单张，减少被杀、观察局势

**自主甩牌（仅庄家方）：** 满足**全部**条件才甩——
- 当前是庄家方（攻方永不主动甩，防止把分甩给对手）
- 拟甩的**每个分量**经记牌推断都是该域铁最大

AI 用自己的记牌推断，**绝不调用 `challenge_dump`**——那需要其他三家手牌，
是引擎裁决专用的开天眼视野。AI 只在自己**有把握**时甩；万一推断错（某张更大
的牌其实在别人手里没出），引擎的 `challenge_dump` 会在 `submit_play` 兜底
降级为最小单张，不会造成非法出牌。**推断保守 + 引擎兜底**是双重保险。

##### 跟牌决策（SMART）

跟牌的牌型被首家锁死，但**跟哪些牌仍是自主决策**。按攻守身份 + 局势选择：

1. **搭档大概率赢墩** → 喂分（出手中分牌 5/10/K）
2. **自己能赢且值得赢**（墩中有分 / 需夺回首出权） → 出最小的能赢的牌
3. **无该花色域、可杀且划算** → 用主牌杀（消耗的主牌价值 < 墩中分值）
4. **赢不了也不值得赢** → 垫牌，此时触发**拆结构保分判断**（见下）

**拆结构保分判断（`strict_follow_structure` 关时生效）：**

宽松跟牌下，若手中有对子/拖拉机但该墩自己赢不了，AI 用评分权衡是否拆开：

- **拆的代价**：失去该结构的牌型优势（后续无法用它压制/首出）
- **保的收益**：拆开后能垫出非分牌、把分牌（5/10/K）留在手里

两者评分谁高听谁的。`strict_follow_structure` 开时此判断被跳过——
有对子必须跟对子，无拆牌自由。

##### 记牌推断（首出跟牌共用）

SMART 依赖局内记牌状态（见 States and Transitions）：
- **已出牌记录**：本局所有已公开打出的牌，逐墩累加
- **铁最大判定**：某牌型是该域铁最大 ⟺ 该域中所有比它大的同型牌都已在
  「已出牌记录」中，或在自己手里。信息来源仅限**公开已出牌 + 自己手牌**，
  无作弊。

**跟牌决策**：

```
ai_follow_decision(hand: Card[], lead: LeadPlay, game_state: GameState, rule_config: RuleConfig) → Card[]
```

MVP 策略：
1. 获取 `get_legal_plays()` 的合法跟牌列表
2. 评估每种合法出牌的分值：
   - **搭档赢墩概率高** → 出分牌（喂分）
   - **自己能赢墩** → 出最小的能赢的牌（节约大牌）
   - **无法赢墩** → 出最小的牌（垫牌）
   - **无首出花色，考虑杀牌** → 评估杀牌收益（墩中分值 vs 消耗的主牌价值）
3. 选择评分最高的出牌

#### 5. 出牌评分函数

```
score_play(play: Card[], context: PlayContext) → float
```

评分因素（MVP 权重）：

| 因素 | 权重 | 说明 |
|------|------|------|
| 赢墩概率 | 0.3 | 基于已出牌推断，当前出牌能否赢墩 |
| 墩中分值 | 0.3 | 该墩已有多少分（值得争夺吗） |
| 牌力消耗 | 0.2 | 出大牌的代价（大牌留着后面用更好？） |
| 分牌保护 | 0.2 | 避免暴露未受保护的分牌 |

权重为 MVP 初始值，后续由 FT4（AI 难度梯度）调整。

### States and Transitions

AI 决策系统无内部持续状态。每次调用时读取当前游戏状态（game_state），执行决策，返回结果。

**SMART 模式所需的局内记牌状态**（跨墩保持，局内有效，局末清空）：
- 已出牌记录（公开信息，逐墩累加）
- 各花色域剩余张数估算（= 全副该域牌 − 已出 − 自己手里）

> ⚠️ **实现现状（2026-09-05）**：`AIPlayer.decide_play` 目前是 **static 纯函数**，
> 无任何记牌状态，SMART 模式尚未实现。落地记牌状态（static → 有状态或外部注入
> 记牌上下文）+ SMART 决策 + 测试是 **S5-05** 的工作。本 GDD 只定义设计契约。

### Interactions with Other Systems

| 方向 | 系统 | 接口 |
|------|------|------|
| ← C2 出牌合法性校验 | `get_legal_plays()` 获取合法出牌列表 |
| ← C1 主副牌判定 | `get_suit_domain()`、`get_sort_value()` 评估牌力 |
| ← C5 分值追踪 | 当前得分，决定策略倾向（保守/激进） |
| ← C7 对局状态机 | AI 出牌轮次时被 C7 调用 |
| ← F3 规则配置系统 | 读取规则配置 |
| → C3 亮主/抢主/反主 | 返回亮主决策 |
| → C4 抠底/配底 | 返回配底决策 |
| → C7 对局状态机 | 返回出牌决策 |

## Formulas

### 赢墩概率估算（MVP 简化版）

```
estimate_win_probability(play: Card[], lead: LeadPlay?, game_state: GameState) → float
```

MVP 策略（简化，不做深度推理）：
- 首出时：该花色域中自己出的牌是否为当前已知最大 → 高概率赢
- 跟牌时：自己的牌是否大于已出的所有牌 → 确定赢/不赢
- 杀牌时：主牌结构是否匹配且大于已出的主牌杀 → 确定赢/不赢

### 牌力评估

```
hand_strength(hand: Card[], trump_suit: Suit?, current_rank: Rank) → float
```

简单统计：
- 主牌数量 / 总手牌数
- 大牌数量（A、K、Q 以及级牌、王）
- 各副花色的控制度（最大牌是否在手）

## Edge Cases

| # | 边界情况 | 处理方式 |
|---|---------|---------|
| E1 | **合法出牌只有 1 种** | 直接出，无需评分 |
| E2 | **AI 为庄家需要配底** | 调用 ai_bury_decision，策略见 Core Rules 第 3 条 |
| E3 | **AI 需要决定是否反主** | MVP 阶段简化：AI 手中有更强声明条件时，50% 概率反主 |
| E4 | **甩牌决策** | SMART 模式下**仅庄家方**在每个分量经记牌推断为铁最大时自主甩牌（见 §4b）；攻方及三个测试开关模式不主动甩牌。AI 绝不调用 `challenge_dump`，推断错误由引擎兜底降级 |
| E5 | **1 副牌下无对子** | AI 决策自然适应——get_legal_plays 不会返回对子选项 |

## Tuning Knobs

| 参数 | 类型 | 默认值 | 影响 |
|------|------|--------|------|
| 评分权重（赢墩/分值/消耗/保护） | float[4] | [0.3, 0.3, 0.2, 0.2] | 调整 AI 出牌风格（激进/保守） |
| 反主概率 | float | 0.5 | MVP 阶段 AI 反主的随机概率 |
| 甩牌启用（庄家方，SMART） | bool | true | 关闭则 SMART 庄家方也不主动甩牌，退回只出 Single/Pair/Tractor |

## Acceptance Criteria

| # | 测试条件 | 预期结果 |
|---|---------|---------|
| AC1 | AI 出牌 100 墩 | 所有出牌均通过 C2 合法性校验（零犯规） |
| AC2 | AI 跟牌时有该花色域的牌 | 不会出其他花色域的牌 |
| AC3 | AI 跟对子时手中有该花色域对子 | 必须出对子（遵守 strict_follow_structure） |
| AC4 | AI 为庄家配底 | 选择的牌数 == bottom_size |
| AC5 | AI 亮主，bid_requires_joker=true 且无王 | 不声明 |
| AC6 | AI 首出，主牌数量占优 | 倾向出主牌清主 |
| AC7 | AI 跟牌，搭档已出最大牌（大概率赢墩） | 倾向出分牌喂分 |
| AC8 | AI 跟牌，无法赢墩 | 出最小的牌垫牌 |

**SMART 模式专属验收（S5-04 定义，S5-05 实现时验证）：**

| # | 测试条件 | 预期结果 |
|---|---------|---------|
| AC9 | SMART 默认生效：不显式传 `lead_strategy` 起一局 | AI 走 SMART 自主决策，首出牌型不再 100% 单张 |
| AC10 | SMART 庄家方首出，某结构经记牌推断为该域铁最大 | 首出该结构（可含甩牌） |
| AC11 | SMART 攻方首出 | 不主动甩牌；倾向拿分或小牌试探 |
| AC12 | SMART 庄家方甩牌，但某分量的更大同型牌其实在对手手里（推断错） | 引擎 `challenge_dump` 兜底降级为最小单张，不产生非法出牌 |
| AC13 | SMART 决策全程 | 从不调用 `challenge_dump`（AI 无他人手牌视野，防作弊） |
| AC14 | SMART 跟牌，`strict_follow_structure=false`，手握对子但该墩赢不了、对子含分牌 | 按评分权衡决定是否拆对子保分（代价 vs 收益） |
| AC15 | SMART 跟牌，`strict_follow_structure=true`，手握该域对子 | 必须跟对子，不触发拆结构判断 |
| AC16 | 显式传 `--lead-strategy simple`（回归基线） | 行为与切换默认前完全一致，批跑基线可复现 |
